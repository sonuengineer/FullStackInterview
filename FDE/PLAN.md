# FDE Content & Study Plan

## Part 1: Content Plan (how to fill each subtopic .md)

Template for every subtopic file:
```
# <Module>
## <Subtopic>
- What it is (2-3 lines)
- Why it matters for an FDE (1-2 lines)
- Key concepts (3-5 bullets)
- Code example / config snippet
- Mini-exercise (build it in 30-60 min)
- Common pitfalls (2-3 bullets)
- Checklist before moving on
```

Rules:
- One subtopic = one sitting (45-90 min), then mini-exercise
- Every code example must run; keep a `snippets/` folder per module
- Link related subtopics across modules (e.g., Module 6 RAG ↔ Module 8 Multimodal)

## Part 2: 5-Month Study Roadmap

- Month 1: 00 Prerequisites + M1-M2 (Python, Linux, APIs) — daily coding
- Month 2: M3-M5 (AWS, Docker/CI-CD, LLM basics) — deploy something weekly
- Month 3: M6-M8 (RAG, Graphs, Multimodal) — build 1 RAG app end-to-end
- Month 4: M9-M14 (Agents, Integration, IAM, Security, Observability) — build 1 agent system
- Month 5: M15-M16 (OmniGuard, AuditMesh capstones) + M17 optional topics

Weekly rhythm: 5 days learn → 1 day build → 1 day review/notes.

## Part 3: FDE Strategy

1. Build in public: push every mini-exercise to GitHub with READMEs
2. Capstones are your portfolio: OmniGuard + AuditMesh = 2 flagship repos
3. Document the FDE process: discovery notes, SOW, ROI slide, UAT runbook (Module 15 deliverables)
4. Ship a deployment: every project must be live (Docker + AWS free tier)
5. Track metrics: latency, token cost, eval scores (Module 14) — put in README
6. Network: post builds on LinkedIn, tag Krish Naik cohort, contribute to MCP/LangGraph communities
7. Apply: target AI engineering / solutions engineering roles; lead interviews with capstone stories

Milestone check: after Month 3 you should have 1 deployed RAG app; after Month 5, 2 capstones + 20+ GitHub repos.
